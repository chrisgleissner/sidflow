# Migration addendum: `u64deck`

An addendum to [Migrating from the 0.5-era data release to 0.8.0](./0.5-to-0.8.md),
covering the parts of that migration specific to consumers of the **full** SQLite export.

Everything in the main guide applies. This page adds the detail relevant to a consumer that
reads `features_json` and the `neighbors` table.

## Asset sizes

| | 0.5-era release | 0.8.0 |
|---|---:|---:|
| `sidcorr-hvsc-full-sidcorr-1.sqlite` | 416 MB | 982 MB |
| `sidcorr-hvsc-full-sidcorr-1.sqlite.gz` | — | 194 MB |
| `sidcorr-hvsc-full-features-1.jsonl.gz` | — | 76 MB |
| `sidcorr-hvsc-full-sidcorr-lite-1.sidcorr` | 3.29 MB | 8.12 MB |
| tracks | 87,073 | 87,868 |
| `neighbor_row_count` | 0 | 2,196,700 |
| `vector_dimensions` | 4 | 58 |

The full export grew because it now carries 25 precomputed neighbours per track and a
58-dimension vector per track. Measured with the July 2026 export audit's run of
`slim_database()` against both exports, a compact database built from the 0.5-era export
retained 37.6 MB and one built from the current export retains 269.4 MB; the difference is
the imported `neighbors` table. 0.8.0 changed no track and no neighbour row relative to the
0.7.0 release, so that figure is the same for both.

## Two assets that carry a subset

Both are new in 0.8.0 and additive. **No existing asset was renamed or removed.**

### `sidcorr-hvsc-full-sidcorr-1.sqlite.gz` — 194,351,886 bytes

The same `sidcorr-1` database, gzipped: 5.05× smaller than the plain `.sqlite`, which
remains published alongside it. Identical schema and contents after decompression.

### `sidcorr-hvsc-full-features-1.jsonl.gz` — 75,933,721 bytes

The raw feature records, without vectors and without neighbours. Line-delimited JSON,
gzipped, sorted by `track_id`, one object per line:

```json
{"track_id": "DEMOS/0-9/Tune.sid#1", "sid_path": "DEMOS/0-9/Tune.sid", "song_index": 1, "features": {}}
```

`features` is the complete 129-key record, unchanged from the `features_json` column of the
full export. The sidecar has its own manifest recording `schema_version`
(`sidcorr-features-1`), `feature_schema_version`, `track_count`, `tracks_without_features`,
`hvsc_version`, `bundle_bytes` and the source SQLite's digest.

A consumer that reads `features_json` and uses neither `vector_json` nor the `neighbors`
table can obtain the same inputs from `sidcorr-hvsc-full-sidcorr-lite-1.sidcorr` (8.12 MB,
for track identity and ratings) plus this sidecar — 84 MB in total.

## The `neighbors` table is populated

The 0.5-era export shipped with `neighbor_row_count: 0`. From 0.7.0 the table holds 25 rows
per track, 2,196,700 in total, ranked by weighted cosine over the 58-dimension vector.

A consumer that prefers a precomputed neighbour cache when one is present, and computes its
own ranking when it is not, will therefore take a different path on this upgrade than it did
on the 0.5-era export. Both remain available:

- **Importing the table** yields SIDFlow's 58-dimension weighted-cosine neighbours. Stored
  depth is 25 per seed. On a partial collection, seeds whose neighbours are largely absent
  locally yield fewer rows after filtering against present paths.
- **Not importing the table** leaves the consumer's own ranking in effect and removes
  approximately 232 MB from a compact database built with `slim_database()`.

Two properties of the stored graph are relevant when using it:

- The neighbour set per seed is fixed at 25, so repeated draws from one seed exhaust it
  sooner than a whole-corpus scan does.
- The rank-1 neighbour is a different subsong of the same `.sid` file for 14.4% of seeds,
  and 905 seeds have all 25 neighbours from their own file. Excluding on `sid_path` rather
  than `track_id` removes same-file siblings.

## Manifest fields

| Field | Since | Notes |
|---|---|---|
| `hvsc_version` | 0.8.0 | Which HVSC release the `sid_path` values belong to, e.g. `"HVSC 85 + Update 85"`. Earlier releases record only `corpus_version: "hvsc"`. |
| `similarity_metric` | 0.8.0 | `"weighted-cosine"` for the 58-dimension vector. |
| `vector_weights` | 0.8.0 | One weight per dimension. Required to reproduce the stored `neighbors` ranking; see the main guide. |
| `neighbor_row_count` | — | From 0.8.0 this is `SELECT COUNT(*) FROM neighbors`. In earlier releases it is `track_count × neighbor_count_per_track`. The two coincide for every published HVSC export. |
| `file_checksums.sqlite_sha256` | — | From 0.8.0 this matches the published file and agrees with `SHA256SUMS`. For earlier releases, `SHA256SUMS` is the authoritative digest. |
| `paths.sqlite`, `paths.manifest` | 0.8.0 | Basenames. Earlier releases may carry an absolute path from the build host. |

The manifest embedded in the database's `meta.manifest_json` omits `file_checksums` entirely
from 0.8.0. Code reading that copy should treat the key as optional.

## Feature coverage

`spectralContrastMean` and `spectralContrastStd` are absent from `features_json` on
approximately 0.14% of tracks (7 of 5,000 sampled). All other keys used by known consumers
are present. No feature keys were removed between `feature_schema_version` 1.3.0 and 1.5.0;
58 were added.

## Release naming

From 0.8.0, a `sidflow-data` release tag is the SIDFlow version that produced it. Earlier
releases keep their `sidcorr-<corpus>-<profile>-<timestamp>` tags unchanged; no release is
retagged, all existing download URLs continue to resolve, and
`releases/latest/download/<name>` is unaffected.
