# Migrating from `sidflow-data` 0.8.0 to 0.8.2

One artefact changed. Everything else in the release carries the byte-for-byte contents it
had in 0.8.0, which the checksums below show directly.

## What changed

`sidcorr-hvsc-full-sidcorr-tiny-1.sidcorr` — the neighbour table and the `graph_flags` field
in the header. Nothing else in the bundle: every `md5_48` file identity, per-file track
count, style mask and packed rating is unchanged, and the file is the same 1,834,993 bytes.

The edges used to be oriented by track ordinal, which is alphabetical `sid_path` position.
That made the exported graph acyclic but shallow — the longest forward path from the median
track was 17 tracks, 28.08% of tracks had no incoming edge, and 3.17% had no outgoing edge.
They are now oriented by a corpus-wide flow order, with slot 0 of every row holding the
track's flow successor. See `doc/similarity-export-tiny.md` §10.3–§10.5 and the 0.8.2 entry
in `CHANGES.md`.

## What each consumer needs to do

**Nothing is required.** `binary_format_version` is still `2`, the section layout is
unchanged, and a reader that does not enforce the old ordinal invariant parses the new bundle
without modification.

**`c64commander`** pins the tiny bundle by tag and digest in
`src/lib/sidRadio/sidcorrRelease.ts`, with a second copy in `scripts/fetch-sidcorr.mjs` that
a test asserts never drifts. Re-pinning to `0.8.2` needs both constants updated. Note what
re-pinning does and does not buy:

- Station membership is unchanged — the style masks are byte-identical, so every tile keeps
  its 17,574 tracks.
- Station *length* is essentially unchanged too. The engine expands at most 8 hops from a
  seed that never moves, so it is bounded by hop budget rather than by the graph. Simulated
  over 300 seeds, the median distinct tracks served before `exhausted` moves from 1,137 to
  1,042, while stations ending within 500 tracks fall from 5.3% to 4.0%.
- To get the 87,868-track stream the data now carries, the engine has to follow slot 0
  forward rather than expand a ball around a fixed seed. That is a client change, not a
  re-pin.

**`u64deck`** consumes the full export and is unaffected: `sidcorr-hvsc-full-sidcorr-1.sqlite`
and its manifest are the same bytes as in 0.8.0, so its `neighbors` import, its slimmed
database and its "♪ More like this" results are all identical.

**Third parties reading the tiny spec.** `doc/similarity-export-tiny.md` §10.3 no longer
requires targets to be lower track ordinals; a reader that validated that rule will reject
0.8.2 bundles and needs to drop the check. Acyclicity itself still holds and is still
verifiable — a topological sort over `3 × track_count` edges is linear. `graph_flags` bit 3
is new and declares that slot 0 is the flow successor; §5.2 already required consumers to
ignore bits they do not recognise.
